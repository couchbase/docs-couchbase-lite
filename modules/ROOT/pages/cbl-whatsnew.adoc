== Release 4.0.0 (October 2025)

Couchbase Lite Release {release} fundamentally transforms document versioning and conflict resolution by introducing version vectors, replacing the traditional revision tree approach.
This architectural change enables superior conflict resolution, improved synchronization performance, and seamless data consistency.

=== New Features

[#version-vectors]
==== Version Vectors

Couchbase Lite 4.0 replaces revision trees with version vectors for document versioning and conflict resolution.
This change aligns Couchbase Lite with Couchbase Server and Sync Gateway, ensuring more consistent behavior in distributed and multi-cluster deployments.

Key changes include:

* **Revision IDs → Versions**:
Each revision is now identified by a version in the format `<timestamp>@<source-id>`.

* **Revision Trees → Version Vectors**:
A version vector is an ordered list of the latest versions from all sources that have modified a document.
This uniquely identifies both the state and history of a document.

* **Hybrid Logical Clocks (HLCs)**:
Timestamps are now based on hybrid logical clocks, enabling last-writer-wins conflict resolution and simpler pruning of old revisions.

For more information about version vectors, see:

* xref:android:version-vectors.adoc[Android - version vectors]
* xref:c:version-vectors.adoc[C - version vectors]
* xref:csharp:version-vectors.adoc[.NET - version vectors]
* xref:java:version-vectors.adoc[Java - version vectors]
* xref:objc:version-vectors.adoc[Objective-C - version vectors]
* xref:swift:version-vectors.adoc[Swift - version vectors]

[#mobile-xdcr-coexistence]
==== Mobile XDCR Coexistence

Couchbase Lite {release} version vector model brings it into alignment with Couchbase Server Cross Data Center Replication (XDCR) and Sync Gateway.
This ensures that documents can sync seamlessly across:

* Mobile-to-Server replication.
* Multi-cluster Couchbase Server environments.
* Peer-to-peer topologies.
