== Release 4.1.0

=== New Features

==== OOTB Support for Peer-to-Peer Sync over Bluetooth Low Energy (BLE) via the Multipeer Replicator

Couchbase Lite 4.1 extends the Multipeer Replicator with Bluetooth Low Energy (BLE) as an additional transport alongside Wi-Fi.
You can now configure the Multipeer Replicator to use Wi-Fi only, Bluetooth only, or both transports simultaneously.

When you enable both transports, the replicator automatically selects the best available transport for each peer and switches between them as network conditions change.
The replicator prefers Wi-Fi when available.
The replicator falls back to Bluetooth when Wi-Fi is unavailable and switches back to Wi-Fi when it becomes reachable again, without interrupting active replication.

BLE transport uses TLS encryption over L2CAP channels, providing the same security guarantees as Wi-Fi transport without requiring device pairing.

Platform requirements for Bluetooth transport:

* iOS 15 or later
* Android API 29 or later

This feature is available on Swift, Android (Kotlin/Java), and Objective-C.

For more information, see:

* xref:swift:p2psync-multipeer.adoc[Swift Multipeer Replicator]
* xref:android:p2psync-multipeer.adoc[Android Multipeer Replicator]
* xref:objc:p2psync-multipeer.adoc[Objective-C Multipeer Replicator]

NOTE: Bluetooth has lower throughput and higher latency than Wi-Fi, and its reliability can decrease as more peers join the Bluetooth network.
Use Wi-Fi as the primary transport for multipeer sync, with Bluetooth as a fallback.

==== Couchbase Lite C++ API Now Supported

Couchbase Lite 4.1 promotes the C++ wrapper API from volatile to a committed, supported API surface for Couchbase Lite C.

As of 4.1, the C++ API is a first-class, committed API with the following guarantees:

* Source compatibility across patch and minor releases within a major line
* Full availability across all Couchbase Lite C platforms, including iOS, Android, Windows, and Linux
* Inclusion in official QA coverage and release testing
* Documented deprecation policy for any future breaking changes

The cbl++ headers ship in all official Couchbase Lite C distributions.
A small set of golden-path examples covering CRUD, query, replication, and logging is available in the documentation.

For more information, see xref:c:index.adoc[Couchbase Lite for C/C++].

==== Windows ARM Support for Couchbase Lite C

Couchbase Lite C 4.1 adds official support for Windows ARM64.
This enables developers targeting ARM-based Windows devices including laptops, tablets, and mini PCs to use Couchbase Lite C with full build and test coverage.

==== Replication Correlation ID

Couchbase Lite 4.1 exposes the Sync Gateway session correlation ID as a read-only property on the replicator.
Sync Gateway generates and sends an `X-Correlation-ID` header during the WebSocket handshake that uniquely identifies each replication session.
You can now read this ID from the replicator and include it in client-side logs to correlate them with Sync Gateway server-side logs when diagnosing replication issues.

This feature is available on all platforms: Swift, Objective-C, Android (Kotlin/Java), C, Java, and .NET.

For more information, see the Monitor section of the replication documentation for your platform:

* xref:swift:replication.adoc#lbl-repl-correlation-id[Swift]
* xref:objc:replication.adoc#lbl-repl-correlation-id[Objective-C]
* xref:android:replication.adoc#lbl-repl-correlation-id[Android]
* xref:c:replication.adoc#lbl-repl-correlation-id[C/C++]
* xref:java:replication.adoc#lbl-repl-correlation-id[Java]
* xref:csharp:replication.adoc#lbl-repl-correlation-id[.NET]

==== Kotlin Serialization Support (Android)

Couchbase Lite 4.1 for Android introduces native integration with `kotlinx.serialization`.

You can now decode Couchbase Lite `Document` and `Dictionary` types directly into `@Serializable` Kotlin data classes without reflection-based workarounds such as Gson or Jackson.
The integration respects Kotlin nullability constraints and default property values during decoding.

This feature is Android-only.

For more information, see xref:android:kotlin-serialization.adoc[Kotlin Serialization].
