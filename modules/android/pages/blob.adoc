[#introduction]
== Introduction

Couchbase{nbsp}Lite for Android uses _blobs_ to store the contents of images, other media files and similar format files as binary objects.

The blob itself is not stored in the document.
It is held in a separate content-addressable store indexed from the document and retrieved only on-demand.

When a document is synchronized, the Couchbase{nbsp}Lite replicator adds an `_attachments` dictionary to the document's properties if it contains a blob -- see xref:android:blob.adoc#img-blob[].


[#blob-objects]
== Blob Objects

The blob as an object appears in a document as dictionary property -- see, for example _avatar_ in xref:android:blob.adoc#img-blob[].

Other properties include `length` (the length in bytes), and optionally `content_type` (typically, its MIME type).

The blob's data (an image, audio or video content) is not stored in the document, but in a separate content-addressable store, indexed by the `digest` property -- see xref:android:blob.adoc#lbl-using[].


[#constraints]
=== Constraints

* Couchbase{nbsp}Lite +
Blobs can be arbitrarily large.
They are only read on demand, not when you load a the _document_.

* sync{nbsp}gateway +
The maximum content size is 20 MB per blob.
If a document's blob is over 20 MB, the document will be replicated but not the blob.

[#syncing]
== Syncing
When a document containing a blob object is synchronized, the Couchbase{nbsp}Lite replicator generates an `_attachments` dictionary with an auto-generated name for each blob attachment.
This is different to the `avatar` key and is used internally to access the blob content.

If you view a sync'd blob document in {cbs} Admin Console, you will see something similar to xref:android:blob.adoc#img-blob[], which shows the document with its generated `_attachments` dictionary, including the `digest`.

[#blob-deletion]
== Blob Deletion and Cleanup

When you delete a document that references a blob, the blob file itself is not immediately removed from the database.
The blob file will be kept in the database until the database is compacted.

To actually remove orphaned blob files from the database, you need to perform database maintenance using the compact option:

.Compact Database to Remove Orphaned Blobs
====

[tabs]
=====

+
